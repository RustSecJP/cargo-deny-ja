# licenses {#licenses}

licenses チェックは、使っているすべてのクレートのライセンス条件が、自分にとって受け入れられるものかどうかを確かめるために使います。cargo-deny は、各クレートが指定しているライセンス要件を、指定された[設定](cfg.html)と照らし合わせて評価し、プロジェクトがそのクレートのライセンス要件を満たしているかどうかを判断します。

```bash
cargo deny check licenses
```

## SPDX {#spdx}

cargo-deny は、クレートのライセンス要件を解釈するのに [SPDX ライセンス式][SPDX] を使います。メタデータから SPDX ライセンス式を直接得られない場合は、指定された確信度のしきい値の範囲で、ライセンス式を導き出そうとします。なお、cargo-deny は現在、クレートに当てはまる可能性のあるすべてのライセンスを見つけるために、すべてのクレートのソースコード全体をくまなく調べることは**しません**。その方法には多くの例外的なケースがあり、人の工夫や、人のミスでさえ、静的にコンパイルされたプログラムの裏をかけてしまうからです。

cargo-deny は、各クレートが自分のライセンス要件を正しく定義していると、善意を前提にして考えます。そのようなデータを自動で集められないという(私たちの経験ではまれな)場合のために、クレートのライセンス要件を手動で指定するしくみを用意しています。

### 式の取得元の優先順位 {#expression-source-precedence}

クレートのライセンス要件の評価に使う SPDX 式は、次の順番で取得されます。

1. そのクレートに[明確化](cfg.html#clarify)が適用されていて、クレートのソースにあるソースファイルがまだ一致している場合は、明確化に書かれた式が使われます。
1. クレートの Cargo.toml マニフェストに [`license`][cargo-md] フィールドがあれば、それが使われます。
1. [`license-file`][cargo-md] フィールドと、ほかの**すべての** `LICENSE(-*)?` ファイルが解析されて SPDX ライセンス識別子が決まります。そして、それらの識別子がすべて `AND` 演算子で結ばれます。つまり、検出されたライセンスの**すべて**を受け入れる必要があります。

_重要な点として_、この優先順位と、ライセンスのデータが正しく扱われているという信頼とを組み合わせると、次のような例外的なケースは扱え**ません**。これはすべてを挙げたリストではなく、チェックを増やしたとしても、プログラムでは完全には防げない種類のことの例です。

1. **欠落**: パッケージのライセンスのデータが不十分な場合です。たとえば、クレートが、リンクしているコードのライセンスを反映していない場合です。
1. **不一致:** Cargo.toml に記載された SPDX 式が、パッケージにある実際のライセンスファイルと合っていない場合、それはチェックされません。
1. **独創性**: ライセンスのデータを、これらの場所以外に置いたり、`LICENSE` 以外で始まる名前にしたりすることもできます。cargo-deny が先に検出して完全だと見なすライセンスのデータがほかにあったとしても、パッケージ内のそのような場所に置かれたものが法的な効力を失う保証はありません。
